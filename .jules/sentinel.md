## 2024-05-18 - Fix Insecure Direct Object Reference (IDOR) in Payroll PDF Generation
**Vulnerability:** The endpoint for downloading a payroll PDF (`KaryawanSlipGajiController@generatePDF`) did not perform ownership or status checks on the `Payroll` object. This meant any authenticated user could potentially download another employee's salary slip simply by guessing or brute-forcing the `payroll` ID. Route Model Binding injected the object directly without authorization checks.
**Learning:** Even if an object is accessed directly via route model binding and obfuscated via `HashIdRoute`, the controller method must explicitly check authorization and ownership against the authenticated user. Endpoints returning files/PDFs are especially prone to this oversight as developers might focus on view generation rather than access control.
**Prevention:** To prevent IDOR vulnerabilities in endpoints accepting objects directly, explicitly verify that the object's `employee_id` belongs to the authenticated user and its state is valid for access (e.g., status is finalized/approved). Always implement authorization checks before proceeding to return files or sensitive views.
