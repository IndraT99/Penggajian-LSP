## 2024-05-14 - IDOR in PDF Generation Endpoints
**Vulnerability:** The `generatePDF` endpoint in `KaryawanSlipGajiController` accepted a `Payroll` object via route model binding (which may use hashed IDs) without subsequently checking if the authenticated user was actually the owner of the `Payroll` record, or if the record's state was finalized (`approved_finance` or `paid`). This could allow attackers to enumerate or guess other users' payroll PDFs.
**Learning:** Route model binding and ID obfuscation (like `HashService` or `HashIdRoute`) are not substitutes for proper authorization. Developers often focus on view generation (like using `Barryvdh\DomPDF\Facade\Pdf`) and forget to apply access controls on endpoints returning files/PDFs.
**Prevention:** Always implement explicit ownership (`$payroll->employee_id === $employee->id`) and state checks (`in_array($payroll->status, ['approved_finance', 'paid'])`) on endpoints returning direct object references, regardless of whether the IDs are obfuscated or not.
