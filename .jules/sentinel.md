## 2024-05-24 - IDOR in PDF Generation Endpoint
**Vulnerability:** Insecure Direct Object Reference (IDOR) on the payroll PDF generation endpoint. The `generatePDF` method in `KaryawanSlipGajiController` accepted a `Payroll` model via route model binding but did not verify if the authenticated user owned the payroll record, nor did it check if the payroll record was in a finalized state (e.g., 'approved_finance' or 'paid'). This allowed any authenticated user to potentially download any other user's payroll slip by guessing or knowing the ID.
**Learning:** Endpoints that generate files or PDFs often get overlooked for authorization checks because developers focus on the view generation logic. Route obfuscation (like the `HashIdRoute` trait used here) is not a substitute for explicit authorization checks, as IDs can still be leaked or enumerated. State checks (like checking if the status is 'approved_finance' or 'paid') are equally important to prevent access to draft or unauthorized records.
**Prevention:** Always implement explicit authorization checks (e.g., `$payroll->employee_id !== $employee->id`) and state checks (e.g., `in_array($payroll->status, ['approved_finance', 'paid'])`) on all endpoints returning direct object references or sensitive files, regardless of route obfuscation techniques.
