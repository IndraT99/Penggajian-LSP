## 2024-05-24 - Fix IDOR in PDF generation endpoint
**Vulnerability:** The `/karyawan/slip-gaji/{payroll}/pdf` endpoint (in `KaryawanSlipGajiController@generatePDF`) generated PDFs by directly passing route models to `Pdf::loadView` without verifying if the requested `Payroll` object belonged to the currently authenticated user or ensuring the payroll was in a finalized state (e.g., `approved_finance` or `paid`). This resulted in an Insecure Direct Object Reference (IDOR) where users could iterate through IDs to view other employees' salary information.
**Learning:** Route model binding does not perform authorization checks by default. We must explicitly verify ownership (comparing `$payroll->employee_id` with `Auth::user()->employee->id`) and state for *every* endpoint returning direct object references or files, even if the user interface only links to the user's own resources.
**Prevention:** Always use explicit `$this->getAuthenticatedEmployee()` and compare IDs. Consider using policies (`$this->authorize('view', $payroll)`) to centralize these checks. When returning sensitive data like PDFs, always ensure the underlying record is fully processed (status check).
