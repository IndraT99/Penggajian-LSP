## 2024-05-18 - Missing IDOR Prevention on PDF Download Endpoint
**Vulnerability:** The `generatePDF` method in `KaryawanSlipGajiController` allowed any authenticated user to download any other user's payroll slip if they could provide a valid payroll ID, despite the route ID obfuscation. The endpoint returned a direct object reference without verifying ownership or that the payroll was in a final state (`approved_finance` or `paid`).
**Learning:** Route obfuscation (like `HashIdRoute`) is not a replacement for proper authorization checks. Obfuscated IDs might be leaked, shared, or eventually guessed. All endpoints that return resources (like PDFs, files, or sensitive data) based on a route parameter must explicitly verify ownership and applicable status, even if the user interface only links to the obfuscated URL.
**Prevention:** Always implement explicit authorization checks (e.g., `$payroll->employee_id !== $employee->id`) and state checks (`!in_array($payroll->status, [...])`) on all resource retrieval endpoints, especially those not utilizing route model binding with explicit scopes or policies.
