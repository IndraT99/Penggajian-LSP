## 2026-10-18 - Insecure Direct Object Reference (IDOR) in Payroll PDF Generation
**Vulnerability:** The `generatePDF` method in `KaryawanSlipGajiController` accepted a `Payroll` object directly via route model binding without verifying if the authenticated user owned the payroll record or if the payroll record was finalized (e.g., status 'approved_finance' or 'paid'). This could allow a malicious user to guess or enumerate the obfuscated ID (if leaked) and access other employees' pay slips.
**Learning:** Endpoints returning files, such as PDFs generated from views, are often overlooked for authorization checks because developers might assume that routing obfuscation (like `HashIdRoute`) or the simple nature of file return implies security. Route obfuscation is not a substitute for explicit authorization.
**Prevention:** Always explicitly check authorization and ownership against the authenticated user for *all* endpoints that accept direct object references, regardless of route obfuscation or if the endpoint simply returns a file/document. Additionally, stateful models like `Payroll` should have their `status` validated before returning data.
