## 2024-06-09 - Insecure Direct Object Reference in PDF Endpoint
**Vulnerability:** IDOR in `KaryawanSlipGajiController::generatePDF`. The method relied on Route Model Binding to fetch a `Payroll` object and generate a PDF without explicitly checking if the authenticated user owned the object. It also failed to check if the state (`status`) of the `Payroll` object was final (`approved_finance` or `paid`).
**Learning:** Route obfuscation (like `HashIdRoute` with `HashService`) is not a replacement for proper authorization checks. Endpoints returning files/PDFs are particularly prone to this oversight as developers might focus solely on view generation. Moreover, checking authorization without checking state can leak draft or unavailable records.
**Prevention:** Always implement explicit ownership checks (e.g., `if ($payroll->employee_id !== $authenticatedEmployee->id)`) and state checks (e.g., `in_array($payroll->status, ['approved_finance', 'paid'])`) against the authenticated user on endpoints returning direct object references, even when IDs are obfuscated.
