## 2025-02-13 - IDOR in PDF Generation Endpoint
**Vulnerability:** Insecure Direct Object Reference (IDOR) on PDF generation. While the `show()` method in `KaryawanSlipGajiController` verified that a user owned a payroll record before displaying it, the `generatePDF()` endpoint blindly accepted the route model binding for `Payroll $payroll` and generated a PDF without any ownership or status checks. This allowed any authenticated user to download the salary slip of any other user if they could guess the hashed ID.
**Learning:** Route obfuscation (using HashIds) does not replace the need for strict authorization checks on endpoints that return objects directly. The assumption that obfuscated IDs cannot be found or guessed is a dangerous one. Additionally, developers sometimes forget to repeat authorization logic from the view endpoint (e.g., `show()`) to the download endpoint (e.g., `generatePDF()`).
**Prevention:** Always implement explicit ownership checks (`$payroll->employee_id === $authenticated_user->employee->id`) and state checks (`status in ['approved_finance', 'paid']`) on EVERY method returning direct object references, regardless of the complexity of the route ID generation or whether a previous endpoint already authorized the same object in the UI.
