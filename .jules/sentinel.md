## 2024-05-18 - Missing Authorization Checks in PDF Generation
**Vulnerability:** The `generatePDF` method in `App\Http\Controllers\Karyawan\KaryawanSlipGajiController` accepted a `Payroll` model instance and generated a PDF slip without verifying if the authenticated user (employee) was the actual owner of the requested payroll slip. Despite the ID being hashed in the route using `HashIdRoute` trait, an attacker could potentially enumerate or reuse captured hashes to access other employees' slip gaji PDFs. Additionally, there was no check to ensure that the payroll status was final (e.g., `approved_finance` or `paid`) before generating the PDF, meaning drafts or rejected slips could be leaked.
**Learning:** Route model binding and hash-based obfuscation do not provide authorization. Direct Object References must always be explicitly authorized against the authenticated user.
**Prevention:** Always implement explicit ownership or permission checks in every controller method that accesses a direct object, especially for actions like file downloads or PDF generation. Validate the state of the object (e.g., status) if only specific states should be accessible.
