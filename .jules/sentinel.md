## 2024-05-24 - [Fix IDOR in Payroll PDF Generation]
**Vulnerability:** Insecure Direct Object Reference (IDOR) on PDF download endpoint (`KaryawanSlipGajiController@generatePDF`). The method accepted a `Payroll` model ID via route model binding without verifying if the authenticated user (employee) was actually the owner of the `Payroll` record, nor verifying the state of the payroll (must be `approved_finance` or `paid`).
**Learning:** Route obfuscation or generic auth middleware is not a replacement for explicit authorization checks. Methods generating files/PDFs are particularly prone to this as developers often focus on the file generation logic and miss the access controls.
**Prevention:** Always implement explicit ownership checks (e.g., `if ($payroll->employee_id !== $authenticatedEmployeeId) { abort(403); }`) and state checks on any endpoint returning a direct object reference or file, regardless of how the ID is provided (e.g., via obfuscated route parameters).
