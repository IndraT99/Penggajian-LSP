## 2024-05-18 - IDOR in PDF Generation
**Vulnerability:** Insecure Direct Object Reference (IDOR) on the `generatePDF` endpoint in `KaryawanSlipGajiController`. The endpoint directly accepted a `Payroll` object (resolved via implicit binding) but didn't verify if the authenticated user owned it or if the payroll was in a finalized state, exposing other employees' sensitive payroll data to anyone authenticated.
**Learning:** Even with route model binding (which may use obscured IDs via `HashService`), explicit access and state checks (`employee_id` == authenticated user ID, and `status` checks) are always required in endpoints that return files or direct references, as obscure IDs can still be guessed or leaked. Developers tend to forget authorization on file generation routes because they focus on the file logic.
**Prevention:** Always verify object ownership (`employee_id` matches) and logical state (`status` is 'approved_finance' or 'paid') before serving the object or generating a file, regardless of whether the ID is hashed in the route.
