## 2025-02-28 - Insecure Direct Object Reference (IDOR) in Payroll PDF Generation
**Vulnerability:** The `generatePDF` endpoint for printing payroll PDFs in `KaryawanSlipGajiController` used route model binding but failed to verify if the authenticated employee actually owned the requested `Payroll` object, allowing any authenticated user to view other users' payroll PDFs by manipulating the ID. It also failed to check if the payroll was in a finalized state.
**Learning:** Route obfuscation using `HashService` or `HashIdRoute` is not a substitute for proper authorization. Endpoints returning files/PDFs are especially prone to this oversight as developers might focus on view generation rather than access control.
**Prevention:** Always implement explicit ownership and state checks on endpoints returning direct object references or files, checking against `Auth::user()->employee->id` and the required object statuses, identical to the checks in the standard `show` endpoints.
