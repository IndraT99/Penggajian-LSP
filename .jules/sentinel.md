## 2024-05-18 - Missing Authorization and Ownership Check on PDF Generation Endpoint
**Vulnerability:** Insecure Direct Object Reference (IDOR). The `generatePDF` method in `KaryawanSlipGajiController` accepted a `Payroll` object directly via route model binding without verifying if the requested payroll record belonged to the authenticated employee or if its status was finalized. This allowed authenticated users to generate PDF salary slips for any employee (including potentially draft records) by guessing the ID.
**Learning:** Endpoints that generate or return files (like PDFs) are often overlooked during authorization implementation, especially when developers rely solely on route model binding to retrieve the object without explicitly verifying ownership against the authenticated user's context. Furthermore, status checks (e.g., 'approved_finance', 'paid') are necessary to prevent access to incomplete or draft documents.
**Prevention:** Always implement explicit authorization checks (e.g., `$payroll->employee_id === $employee->id`) and state validation (e.g., checking `$payroll->status`) on all controller methods that accept direct object references, regardless of the output format (view, JSON, PDF download). Do not rely on obfuscated route keys or obscurity as a substitute for access control.
