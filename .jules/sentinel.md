## 2024-05-24 - Insecure Direct Object Reference (IDOR) in PDF Generation
**Vulnerability:** The endpoint for generating payroll PDF slip (`/karyawan/slip-gaji/{payroll}/pdf`) did not implement authorization and ownership checks. Despite the model using hashed route keys (via `HashIdRoute`), any authenticated user could potentially view or download other employees' sensitive payroll data if they obtained or guessed the hashed ID.
**Learning:** Route obfuscation (like hashing IDs) is not a substitute for proper access control. Endpoints returning files/PDFs are particularly prone to this oversight as developers might focus on view generation rather than access control, similar to direct object access in API endpoints.
**Prevention:** Always implement explicit ownership checks (e.g., comparing `employee_id` with the authenticated user's ID) and state checks (e.g., verifying the payroll status is final) on all endpoints that return direct object references, including file downloads and PDF generations.
