## 2024-05-23 - [Insecure Direct Object Reference (IDOR) in PDF Generation]
**Vulnerability:** The `generatePDF` method in `KaryawanSlipGajiController` allowed any authenticated employee to download the payroll slip PDF of any other employee if they could guess or obtain the payroll ID. It also lacked a status check, potentially exposing draft or unapproved payroll slips.
**Learning:** Endpoints that generate or return files (like PDFs) using direct object references (even if obfuscated by Route Model Binding) are common blind spots for authorization. Developers may focus on the view generation logic and overlook the access control checks, assuming that because the ID is obfuscated, it's secure. Route obfuscation is NOT authorization.
**Prevention:** Always implement explicit authorization checks (e.g., verifying ownership against `Auth::user()->employee->id`) and state checks (e.g., `$payroll->status`) on all endpoints, particularly those returning files or direct object representations, regardless of whether the IDs are obfuscated.
