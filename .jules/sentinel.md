## 2024-05-23 - Insecure Direct Object Reference (IDOR) on PDF Download Endpoint
**Vulnerability:** The `generatePDF` method in `KaryawanSlipGajiController` accepted a route-model bound `Payroll` instance but directly generated and returned the PDF without checking if the authenticated user owned the payroll record or if the payroll was in a finalized status. This allowed any authenticated employee to download arbitrary payroll PDFs by guessing or enumerating IDs.
**Learning:** Endpoints that generate or return files (like PDFs) based on a direct object reference must explicitly implement the same authorization and status checks as the view endpoints (like `show`). Route model binding and obfuscated IDs (via `HashService`) do not substitute for proper authorization.
**Prevention:** Always verify ownership (`$model->user_id === Auth::id()`) and necessary business logic states (e.g., `status === 'approved'`) before returning sensitive data or generating documents, even if the IDs are obscured.
