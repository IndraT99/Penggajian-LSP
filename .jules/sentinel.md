## 2024-05-24 - IDOR in PDF Generation Endpoint
**Vulnerability:** Insecure Direct Object Reference (IDOR) on the `KaryawanSlipGajiController::generatePDF` endpoint. The endpoint directly accepted a `Payroll` object via route model binding and generated a PDF without verifying if the authenticated user's employee ID matched the payroll's `employee_id`, and without verifying if the payroll was in a final state.
**Learning:** Endpoints returning files or PDFs are especially prone to IDOR because developers often focus on the file generation logic (e.g., using `Barryvdh\DomPDF`) rather than access control, assuming obfuscated route IDs or the complexity of the URL are sufficient protection.
**Prevention:** Always explicitly check authorization (ownership) and entity state (e.g., status fields like 'approved_finance' or 'paid') on endpoints that return direct object references, even if the route key is obfuscated (e.g., using HashIdRoute). State verification is crucial to prevent unauthorized access to draft or unapproved records.
