## 2024-10-08 - Fix Insecure Direct Object Reference (IDOR) in PDF generation
**Vulnerability:** The `generatePDF` method in `KaryawanSlipGajiController` accepted a `Payroll` object via route model binding and generated a PDF for it without verifying that the payroll actually belonged to the authenticated employee or checking the payroll's status. This allowed any authenticated user to potentially download any other user's payroll slip if they could guess the ID.
**Learning:** Endpoints that generate files (like PDFs or exports) are often overlooked when applying authorization checks, especially if they are added later or considered "utility" endpoints. Developers sometimes assume obfuscated IDs or routing are sufficient, or simply forget to add the standard ownership and state checks (like `$payroll->employee_id !== $employee->id` and `$payroll->status` checks) that might be present in standard `show` or `index` views.
**Prevention:** Always explicitly verify authorization and ownership against the authenticated user for ANY endpoint that directly references an object, even if the route uses obfuscated IDs. Ensure that endpoints returning files or exports have the same or stricter access controls as endpoints displaying the data in HTML views.
