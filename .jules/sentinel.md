## 2023-10-27 - [Insecure Direct Object Reference (IDOR) on PDF Download]
**Vulnerability:** The `/karyawan/slip-gaji/{payroll}/pdf` endpoint (served by `KaryawanSlipGajiController@generatePDF`) lacked ownership and status validation checks on the directly accessed `Payroll` object, allowing any authenticated employee to download the payroll slip of another employee if they knew or guessed the obfuscated route ID.
**Learning:** Endpoints that generate or serve files/PDFs using route model binding can easily be overlooked for authorization checks, since developers focus primarily on the file generation logic (e.g., using `Pdf::loadView`). Route obfuscation (via `HashService` or `HashIdRoute`) is not a sufficient replacement for explicit access controls.
**Prevention:** Always implement explicit ownership checks (e.g., `$payroll->employee_id !== $employee->id`) and state validation checks (e.g., `$payroll->status` is `approved_finance` or `paid`) on every controller method that accesses resources via direct object reference, even if they return a file or are "read-only".
