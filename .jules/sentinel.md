## 2025-02-14 - IDOR in PDF Generation Endpoint
**Vulnerability:** The `generatePDF` method in `KaryawanSlipGajiController` allowed any user to generate and view a PDF of any `Payroll` record using its ID, without checking if the payroll belonged to the authenticated user or if the payroll was in an approved status. This is a classic Insecure Direct Object Reference (IDOR).
**Learning:** Endpoints that generate files (like PDFs) or return direct object representations can easily slip past authorization checks if the developer focuses solely on the generation logic instead of the access control. The route used model binding, but implicit model binding doesn't enforce ownership.
**Prevention:** Always implement explicit authorization checks (e.g., matching `$model->user_id` with `Auth::id()`) inside endpoints that handle direct object references, particularly those serving files or sensitive documents. Additionally, check the data state (e.g., `status`) to ensure draft or unapproved data isn't leaked.
