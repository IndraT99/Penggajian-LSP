## 2024-05-18 - Fix Insecure Direct Object Reference (IDOR) in PDF Generation Endpoint
**Vulnerability:** The `/karyawan/slip-gaji/{payroll}/pdf` endpoint (handled by `KaryawanSlipGajiController::generatePDF`) lacked proper authorization checks. Although the controller correctly fetched the `Payroll` model via route model binding (which might be obfuscated), it failed to verify that the retrieved `Payroll` actually belonged to the currently authenticated user. Additionally, it did not check if the `Payroll` status was in a finalized state (`approved_finance` or `paid`). An attacker could manipulate the obfuscated `{payroll}` ID to download slip gajis of other employees or view unapproved payrolls.
**Learning:** Endpoints returning files, downloads, or PDFs are easily overlooked for authorization checks because developers often focus on the generation logic (e.g., loading a view into DOMPDF) rather than the access control, assuming obfuscated IDs provide security (which they do not). State checks on entities (like verifying a payroll is 'paid') are also critical security controls.
**Prevention:** Always apply the exact same authorization and state verification logic to file download/PDF generation endpoints as you do to the endpoints that display the data on screen. Never rely solely on route obfuscation or route model binding for security. Explicitly check ownership (`$payroll->employee_id === $employee->id`) and state (`in_array($payroll->status, [...])`) before returning sensitive content.
